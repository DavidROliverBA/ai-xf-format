# E13 results: a canonical serialisation for AI-XF concepts

**2026-10-03.** Pre-registered: the hypotheses and pass marks in
[`PLAN.md`](./PLAN.md) were committed (`c610e31`), then hardened before the
first run (`2196ce2`: no third-party download, containers on 127.0.0.1, and a
stricter H2). Re-run with `run.sh`; numbers in `results.json`. Python 3.14 with
PyYAML, bun 1.3 with `yaml` 2.9.0, `postgres:17`.

**Corpus:** 192 concepts from nine bundles and four kinds of producer: hand-written
(`examples/`, the two fixtures, the three E2 bundles), the vault exporter
(`psychology-kb` 102, `ai-concepts-kb` 63), and KnowledgeX (4, saved from E9).
The optional Longview export was left out, as recommended for this run.

## Results

| # | Hypothesis | Result | Pass |
|---|---|---|---|
| H1 | Idempotent | 192 / 192, both implementations | **yes** |
| H2 | Meaning preserved | 192 / 192 data models equal; validator findings identical before and after on all 9 bundles under both parsers (18 comparisons); 0 whole-number floats in the corpus | **yes** |
| H3 | Two implementations agree | Python and TypeScript byte-identical on 192 / 192 | **yes** |
| H4 | Survives Postgres `jsonb` | 192 / 192 regenerated byte-identical (E10 baseline: 0 of 172) | **yes** |
| H5 | Hash tracks meaning | (a) 1,536 / 1,536 formatting-only variants hash the same; (b) 767 / 767 single-value mutations hash differently | **yes** |
| H6 | Reads the same in YAML 1.1 | 192 / 192 | **yes** |

The variants are not trivial. On a sample of 37 concepts, every one of the eight
kinds (keys shuffled, flow lists, single quotes, lists at column 0, wrapped
lines, CRLF, extra blank lines, comments) differed from the canonical bytes, and
the variant generator never changed meaning (0 discarded). One concept has no
list, so it has three mutations, not four: 767, not 768.

**Diagnostic: no producer writes canonical files today, 0 of 192.**

| Producer | Typical differences |
|---|---|
| Vault exporter (PyYAML) | long strings wrapped onto two lines; lists at column 0; timestamps quoted; custom keys in its own order |
| Hand-written `examples/` | flow lists (`tags: [data, orders]`); extra blank lines |
| KnowledgeX | its own key order; a date-only custom key (`created: 2026-10-02`) written unquoted |

That is expected for a form that did not exist until now, and it is why the
gate is canonicalising *on write*, not a convention producers already follow.

## What the passes do and do not show

- **The rules are exact enough to implement twice.** Two implementations,
  written separately from `CANONICAL.md` in two languages with two YAML
  libraries, agreed on every byte. That is the strongest result: it is what
  makes a cross-system content hash possible.
- **E10's database problem is solved.** Fields stored as `jsonb` (keys
  reordered) regenerate the identical file, so a database can hold concepts as
  fields and still hand out the same bytes and hash as a file system.
- **One caveat the pass marks do not catch.** H6 compares what a YAML 1.1
  reader sees in the *canonical* file with the YAML 1.2 model, and they agree.
  But a 1.1 reader saw KnowledgeX's unquoted `created: 2026-10-02` in the
  *original* as a date; the canonical form quotes it (only the five timestamp
  keys of §5 stay plain), so the same reader now sees a string. This affects
  only date-only values under custom keys; AI-XF's own timestamps are
  datetimes and stay plain. Open question for the spec text: list the
  timestamp keys, or keep any value that matches an ISO date or datetime
  plain.
- **Limits.** One run, one machine. The corpus has no deeply nested custom
  structures, no non-ASCII keys, no integers above 2^53 (which JavaScript cannot
  hold exactly) and no whole-number floats; the rules cover them, but only the
  last is measured, by its absence. Longview's export was not in the corpus.

## Decision this supports

All six hypotheses pass, so by the plan the canonical form and the `sha256:`
content hash can be proposed for AI-XF v0.5: a SHOULD for producers that
regenerate files and for any system that stores concepts as fields, with
`CANONICAL.md` as the normative text. Before that, settle the date-only
question above, and add Longview's export to the corpus (`E13_LONGVIEW=1`) so
the second real producer is measured too.
